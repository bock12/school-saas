## 2. Invariants & Acceptance Criteria
- **AC-001 (Zero Module-Level Admin Clients):** Targeted routes must not instantiate `createAdminClient()` at the module top level.
- **AC-002 (Privileged Client Boundary):** No admin client may be instantiated before `authorizeApiRequest()` succeeds. Unauthorized requests must never invoke the admin client factory.
- **AC-003 (Untrusted Client Tenant Identifiers):** Client-supplied tenant identifiers are treated strictly as untrusted requested targets (`requestedTenantSlug`). All operations bind strictly to `auth.tenantId`.
- **AC-004 (Method-Specific Role Enforcement):** Roles are verified against repository truth and differentiated by HTTP method (e.g. DELETE `/api/admissions` restricted strictly to administrators; `exam_officer` denied).
- **AC-005 (Strict Tenant Analytics — Zero NULL Leakage):** Every query in `/api/exam-office/dashboard` must be strictly constrained by `.eq('tenant_id', auth.tenantId)`. No `.or('tenant_id.is.null')` fallback is permitted.
- **AC-006 (IDOR / BOLA Prevention):** Updates and deletions require resource authorization and query constraint by both resource `id` and `auth.tenantId`. Client-supplied tenant reassignment is blocked.
- **AC-007 (Dedicated Security Test Suite):** Standalone test suite `tests/security/privileged-api-containment.test.ts` covers authentication, RBAC, tenant isolation, IDOR defense, and admin-client containment.
- **AC-008 (TASK-0004 Regression Verification):** Regression verification confirms existing routes preserve all security invariants.
- **AC-009 (Build & Quality Verification):** `npx tsc --noEmit`, `npm run lint`, unit/security tests, and `npm run build` exit with code 0.
