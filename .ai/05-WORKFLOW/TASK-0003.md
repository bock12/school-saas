## Investigation Scope
The investigation must thoroughly examine, at minimum, the following surfaces and dimensions:
- `/api/admin/exams` (examination overview, sessions, results approval, malpractices)
- `/api/test-db` (database connectivity diagnostics and exposure)
- `/api/admissions/*` (applicant submission vs. privileged officer review endpoints)
- `/api/cass-export/*` (continuous assessment score sheet export and reports)
- `/api/super-admin/*` (platform administration and tenant provisioning endpoints)
- `src/app/actions/academic-calendar.ts` (calendar events and session management)
- `createAdminClient()` call sites across the entire application
- Supabase service-role usage and direct PostgreSQL callers
- Authentication & session verification boundaries
- Tenant resolution mechanisms and fallback behaviors
- Tenant isolation enforcement at edge, application, and database layers
- RBAC and role/permission checks across protected handlers
- Resource-level and object-level authorization (ownership validation)
- Middleware vs. API route matcher boundaries (e.g. edge exclusion in `src/middleware.ts`)
- Row Level Security (RLS) interaction and policy coverage
- Response and data minimization (leakage of internal IDs, metadata, or other tenants' data)
- Cross-tenant access, enumeration, and tampering risks

## Evidence & Classification Rules
1. **Taxonomy:** Every finding must be explicitly classified using repository truth standards:
   - `CONFIRMED`: Directly observed and verified in source code or configuration.
   - `INFERRED`: Logical architectural deduction supported by code patterns but not directly verified at runtime.
   - `NOT VERIFIED`: Static analysis cannot determine reachability or runtime configuration.
2. **Evidence Standard:** Every `CONFIRMED` finding must cite exact file paths and line numbers/code excerpts. Never present an inference or assumption as confirmed repository fact.

## Required Deliverables from Gemini
Gemini must produce an exhaustive security architecture investigation report containing:
1. **Security Findings:** Detailed enumeration of vulnerabilities, misconfigurations, and architectural anti-patterns.
2. **Affected Files & Call Sites:** Comprehensive inventory of impacted routes, actions, and utilities.
3. **Existing Controls:** Current defenses, middleware matchers, and guard functions observed.
4. **Control Gaps:** Specific omissions in authentication, tenant verification, RBAC, or object checks.
5. **Severity & Impact:** Risk assessment aligned with AI-EOS risk criteria (`Critical`, `High`, `Medium`, `Low`).
6. **Attack Scenarios:** Concrete threat vectors and exploit pathways where applicable (sanitized, conceptual).
7. **Remediation Options:** Comparative analysis of architectural approaches to resolve each gap.
8. **Recommended Remediation:** Recommended technical path with design justifications.
9. **Regression-Test Requirements:** Exact specifications for positive, negative, cross-tenant, unauthenticated, and wrong-role test cases needed to prove containment.
10. **Implementation-Task Recommendations:** Proposed discrete task contracts (e.g., `TASK-0003A`, `TASK-0003B`, etc.) to execute the approved remediation safely in subsequent tasks.
